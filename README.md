# ipago-js

Public JavaScript packages for [iPago](https://ipago.io):

| Package | Version | What it is |
| --- | --- | --- |
| [`@ipago/sdk`](packages/sdk) | 0.1.0 | Server-side API client and webhook signature verification. Node 18+ (or any runtime with `fetch` and WebCrypto). |
| [`@ipago/checkout`](packages/checkout) | 0.0.0 | Browser pre-checkout form that mounts Stripe Embedded Checkout. No secret keys. |

The packages are versioned independently. Publish each one from its own tag.

## Requirements

- Node.js 18 or newer
- pnpm 10.33.0 (`packageManager` in the root `package.json`; Corepack will select it)

Lint, typecheck, test, and build run offline.

## Install

```bash
corepack enable
pnpm install
```

## Lint, typecheck, test, build

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

Each command covers both packages. Package scripts are `build`, `typecheck`, and `test` inside `packages/sdk` and `packages/checkout`.

`pnpm --filter @ipago/checkout build` writes `packages/checkout/dist/checkout.global.js`. The demo at `packages/checkout/demo/index.html` loads that file. It is a static page: session creation still has to be implemented by the merchant server.

## Environment

Copy `.env.example` when integrating the SDK. The test suite ignores these variables.

| Variable | Used by |
| --- | --- |
| `IPAGO_SECRET_KEY` | Your server, passed to `new IPago({ apiKey })`. Placeholder only in `.env.example`. |
| `IPAGO_WEBHOOK_SECRET` | Your server, passed to `constructWebhookEvent`. Placeholder only in `.env.example`. |
| `PLATFORM_READ_TOKEN` | Optional. `pnpm generate:sdk <release>` when `ipago/platform` is private. |

`@ipago/checkout` takes only the public `publishableKey`.

## SDK types

`packages/sdk/src/schema.d.ts` is generated by `openapi-typescript` 7.13.0 from the OpenAPI document pinned at `packages/sdk/openapi/openapi.json`. `packages/sdk/openapi/pin.json` records the `ipago/platform` release that document came from.

`scripts/generate-sdk.mjs` replaces the old generator input `../../apps/api`. Pass a platform release:

```bash
pnpm generate:sdk v1.4.0
```

That downloads the `openapi.json` release asset (or the document at that tag), updates the pin, and rewrites `schema.d.ts`. Check the diff before committing it.

```bash
pnpm generate:sdk --from-pin
```

regenerates from the committed spec and should produce no diff. CI runs this and fails if the types drift.

The pinned document currently has `"release": "unreleased"`: `ipago/platform` has not published a release yet. It is the `openapi.json` that `pnpm openapi:gen` writes on `ipago/platform` `main`, copied into `packages/sdk/openapi/openapi.json` and regenerated with `pnpm generate:sdk --from-pin`. Replace the pin by running `pnpm generate:sdk` against a real platform release when one is published.

## Publish

CI on `main` lints, typechecks, tests, and builds. Publish by pushing a tag that matches the package version:

- `sdk-v0.1.0` publishes `@ipago/sdk` at the version in `packages/sdk/package.json`
- `checkout-v0.0.0` publishes `@ipago/checkout` at the version in `packages/checkout/package.json`

The release workflow (`.github/workflows/release.yml`) refuses a tag whose version does not match `package.json`. It builds via `prepublishOnly` and publishes to npm with `access: public`.

Set the `NPM_TOKEN` GitHub Actions secret to an npm token that can publish `@ipago`. The workflow maps it to `NODE_AUTH_TOKEN` for the npm registry. Keep the token in GitHub Actions secrets.

These packages publish to npm.
